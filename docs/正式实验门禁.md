# 正式实验门禁

状态：2026-09-22。项目仍处于数据与方法学预备阶段；本页列出禁止将结果称为正式基因组预测结论的条件。

## 已完成的预备证据

- AraPheno API 全目录 536/536 条目已取得；紧凑、可版本控制的结果见 [feasibility registry](../data/manifests/arapheno_feasibility_registry_2026-09-22.tsv)。它记录 row 数、唯一 accession 数、1135G 交集、重复计数、群体组成及每份 values 响应的 SHA256。
- 在“1135G交集至少700且 API 无重复 accession”这一**仅作筛查**的条件下，条目 701/702/703（DTF）与 704（RL，850）、705（CL，904）出现。RL/CL 是非 flowering 的高样本候选，但名称、实验单位、原始研究中的 accession-level 汇总定义尚未核实，因而没有被选为正式 sentinel。
- binary HDF5 全文件扫描确认所有 10,709,949 位点只含 0/1；minority-state accession count≥5 位点为 4,845,760。此分支只能作方向不变的密度、关系矩阵、PCA/近亲与位置感知预备分析；尚无完整 density prediction runner。
- formal CLI 模式以 `gate_v2` 拒绝任何非 `at_pheno_formal_v2` 的 `provenance.json`（重算而非信任）：逐次运行重算 `genotypes.npy`、`samples.tsv`、`variants.tsv`、`phenotypes.tsv`、trait-resolution registry 与 SHA256 绑定的 source-manifest JSON 共 **6 个 SHA256**（源文件或状态文件一旦被改动则必被发现）；`source_vcf_sha256` 为 **record-only** 记录域：64-hex 形式校验＋与 manifest 记录交叉绑定（`local_sha256`/`official_md5`/`md5_matches_official`），执行 gate 不重读 19 GB raw VCF，raw-file 一致性核验由 dataset-build 阶段的 `verify_source_vcf` 承担；官方 source MD5 **经 SHA256 绑定的 source-manifest JSON 交叉校验**：`local_sha256 == source_vcf_sha256`、`official_md5 == official_source_md5`、`md5_matches_official: true`——gate **不**对 19 GB 级 VCF 做再哈希，MD5 匹配是 manifest 记录声明，**不得**称 formal gate 自行验证了 official MD5；raw-file 与官方同源的一至性审计由 dataset-build 阶段脚本承担（重算该文件 SHA256 与 MD5，对 manifest 记录逐字段校验）；trait 真值以 **SHA256 绑定的 registry TSV 为准**：requested trait 在 registry 中必须唯一存在，且 `target_status == PUBLISHED_ACCESSION_VALUE_USABLE`，provenance 内嵌 `phenotype_registry.resolved=true` 仅在与 registry 真值一致时允许，registry 处于 `REQUIRES_DUPLICATE_RESOLUTION` 等其它状态时 MUST FAIL；过滤/multiallelic policy、TAIR10、`ALT_dosage_0_1_2`、转换脚本/commit；拒绝信息显式给出缺/错的字段名；v1 记录不再被门禁接受；`variants.tsv` 强制按 `(chromosome, position, REF, ALT)` 严格递增。

## 尚未冻结的 P0 条件

1. **正式 genotype。** 从 VCF 验证 REF/ALT、原始 missing、杂合与 HDF5 position 映射；写入可复算转换和 provenance。**2026-09 冻结的 int8 存储契约**：dtype `int8`、值域 `{-1, 0, 1, 2}`（-1 缺失，0/1/2 ALT dosage）、shape `sample × variant`；**禁止先经 float32 全量矩阵生成**；`load_dataset`/`fit_qc`/`additive_kernel` 的 `-1` 缺失语义与 GT round-trip fixture（`0/0, 0/1, 1/1, ./.` → `0, 1, 2, -1`）已落地并配最小 fixture test。10.7M 站点级的正式 VCF→int8 转换**尚未实施**；raw-file 审计由 build 阶段 `at_pheno.formal_provenance.verify_source_vcf` 承担（重算 raw 文件 SHA256 / MD5、对照 source-manifest 记录逐字段校验；执行 gate 不重读 19 GB 源文件）。
2. **性状 target。** 对拟入选 traits 回到原研究/官方 accession-level 表，登记 `target_level`、重复定义、汇总方法与来源、排除记录、final_n。不满足 "registry `target_status == PUBLISHED_ACCESSION_VALUE_USABLE`（provenance 的 `resolved=true` 须与之一致）" 的性状不得创建 formal split。
3. **近亲块。** 官方 `kinship_ibs_mac5.hdf5` 的非对角值尺度约 6.00–7.32，而非 0–1；不能套用 0.95。`scripts/audit_kinship_blocks.py` 只导出原尺度敏感性组件。须根据其定义、IBS/近克隆诊断与有效样本量选择阈值，并将 block manifest 固定后再跑确认性评估。
4. **确认性推断。** G1 前注册 primary contrast、SESOI、重采样单位和 multiplicity family。PCC 为主展示；另以 kinship-block 的 paired squared-error 差或 Q² 作可分解的确认性辅助指标。不得用“p>0.05”替代等效/实用无增益结论。

## 执行顺序

先用 HDF5 orientation-invariant branch 完成 density、PCA 与近亲诊断，同时构建 VCF ALT branch；随后解决 trait aggregation、冻结近亲 blocks 与确认性计划；只有此后才开始 G1 的正式 additive/GBLUP 基线。外部 rrBLUP/BGLR/GCTA 类实现的一致性检查须在中等 marker 数的正式 ALT 输入上完成，不能用当前内部数值等价测试替代。

## v2 gate 的 blast radius

`at_pheno_formal_v2` 收紧的是 **绑定层**，不是 genotype 生产本身：

- **P0-1（正式 genotype）仍然 OPEN**：v2 gate 只提供"已产物必须被验证"的机制；真正的 12 GB ALT-dosage `genotypes.npy` 在 VCF 语义验收（FILTER policy 可复算、坐标映射对齐、spot-check 无系统偏移）完成前不得通过此门禁——它不会因 schema 通过就释放。**未决 P0-1 实施方案**：int8 存储契约（见本页"尚未冻结的 P0 条件" §1）与 build 阶段 `verify_source_vcf` raw-file 审计已就绪；10.7M 站点 VCF→int8 转换尚未实施。
- **以下四项未由本 gate 冻结**（对应交付包里的未定 sections，属已知 UNRESOLVED）：HDF5 0/1 orientation 的 REF/ALT 等价性判定；跨版本对齐/multiallelic 的属性声明；SESOI；12-trait panel。这些在冻结前不影响 v2 记录的有效性；但一旦输入或策略状态改变，`vcf_filter_policy`/`multiallelic_policy`/`allele_encoding` 三项声明与 **SHA 绑定集合（6 项运行重算——4 项 data 文件 + registry TSV + SHA256 绑定的 source-manifest JSON；另加 record-only `source_vcf_sha256`，由 manifest 交叉绑定、不经 gate 重读）** 会在下一次 gate 命中重新校验。
- P0-2（trait target 登记）中"未 `resolved=true` 的 trait 不得创建 formal split"由 `gate_v2` 对照 **SHA256 绑定的 registry TSV 真值**校验：requested trait 在 registry 中必须唯一存在、且 `target_status == PUBLISHED_ACCESSION_VALUE_USABLE`；`phenotype_registry.resolved=true` 仅在与该真值一致时允许，registry 处于 `REQUIRES_DUPLICATE_RESOLUTION` 等其它状态时 MUST FAIL（fixture test `test_registry_duplicate_blocked_rejects_resolved_record` 锁定）。P0-3/P0-4 不受 v2 改动。
- pilot 通道（合成 demo 数据、最小 provenance）与 v1 记录在 pilot 语境保持可读，但 v1 记录在正式通道按缺失 `provenance_schema` 字段被拒。
