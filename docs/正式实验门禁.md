# 正式实验门禁

状态：2026-09-22。项目仍处于数据与方法学预备阶段；本页列出禁止将结果称为正式基因组预测结论的条件。

## 已完成的预备证据

- AraPheno API 全目录 536/536 条目已取得；紧凑、可版本控制的结果见 [feasibility registry](../data/manifests/arapheno_feasibility_registry_2026-09-22.tsv)。它记录 row 数、唯一 accession 数、1135G 交集、重复计数、群体组成及每份 values 响应的 SHA256。
- 在“1135G交集至少700且 API 无重复 accession”这一**仅作筛查**的条件下，条目 701/702/703（DTF）与 704（RL，850）、705（CL，904）出现。RL/CL 是非 flowering 的高样本候选，但名称、实验单位、原始研究中的 accession-level 汇总定义尚未核实，因而没有被选为正式 sentinel。
- binary HDF5 全文件扫描确认所有 10,709,949 位点只含 0/1；minority-state accession count≥5 位点为 4,845,760。此分支只能作方向不变的密度、关系矩阵、PCA/近亲与位置感知预备分析；尚无完整 density prediction runner。
- formal CLI 模式要求 `provenance.json`：实际 `genotypes.npy` 的 SHA256、VCF source hash、转换脚本/commit、TAIR10、ALT encoding 和匹配 trait 的 `resolved=true` registry 都会检查；`variants.tsv` 强制按 `(chromosome, position, REF, ALT)` 严格递增。

## 尚未冻结的 P0 条件

1. **正式 genotype。** 从 VCF 验证 REF/ALT、原始 missing、杂合与 HDF5 position 映射；写入可复算转换和 provenance。
2. **性状 target。** 对拟入选 traits 回到原研究/官方 accession-level 表，登记 `target_level`、重复定义、汇总方法与来源、排除记录、final_n。未 `resolved=true` 的性状不得创建 formal split。
3. **近亲块。** 官方 `kinship_ibs_mac5.hdf5` 的非对角值尺度约 6.00–7.32，而非 0–1；不能套用 0.95。`scripts/audit_kinship_blocks.py` 只导出原尺度敏感性组件。须根据其定义、IBS/近克隆诊断与有效样本量选择阈值，并将 block manifest 固定后再跑确认性评估。
4. **确认性推断。** G1 前注册 primary contrast、SESOI、重采样单位和 multiplicity family。PCC 为主展示；另以 kinship-block 的 paired squared-error 差或 Q² 作可分解的确认性辅助指标。不得用“p>0.05”替代等效/实用无增益结论。

## 执行顺序

先用 HDF5 orientation-invariant branch 完成 density、PCA 与近亲诊断，同时构建 VCF ALT branch；随后解决 trait aggregation、冻结近亲 blocks 与确认性计划；只有此后才开始 G1 的正式 additive/GBLUP 基线。外部 rrBLUP/BGLR/GCTA 类实现的一致性检查须在中等 marker 数的正式 ALT 输入上完成，不能用当前内部数值等价测试替代。
