# 数据与运行契约

## 原始证据

`data/raw/` 保存不可手工修改的下载快照，按来源/日期分目录。每份资源记录 URL、时间、字节数、SHA256、版本、许可/使用要求（来自官方说明）和处理状态。原始大文件不入 Git；小型manifest和审计摘要可进入 `data/manifests/`、`docs/`。不得根据表型名字猜测 accession ID 映射。

已下载的官方HDF5是预插补binary格式，当前没有REF/ALT，尚不满足下面的正式ALT输入契约。文件级维度/ID核验不等于训练输入语义已合格；不得填造REF/ALT以绕过校验。

方向不变HDF5预备分支的限制和已核验值域见 [HDF5分支说明](方向不变HDF5分支.md)。它使用独立实现，不能写成`variants.tsv`的伪ALT输入，也不能以formal mode运行。

AraPheno 快照工具只下载目录及指定候选；不自动选择正式性状，也不静默汇总重复值。下载失败在manifest留痕并非零退出。

## CPU pilot 输入

一个目录包含以下文件，文件行序就是矩阵轴的唯一依据。

| 文件 | 必需字段/形式 | 规则 |
| --- | --- | --- |
| `genotypes.npy` | 数值二维array，行sample、列variant，即 shape = `n_samples × n_variants` | float：ALT dosage硬调用0/1/2、NaN缺失；int8正式存储契约（P0-1，2026-09冻结）：dtype `int8`、值域 `{-1,0,1,2}`（-1缺失，0/1/2 ALT dosage），契约禁止经 float32 全量矩阵生成。两种编码均不接受概率dosage；通过mmap读取 |
| `samples.tsv` | `accession_id`, `genetic_group` | canonical字符串且唯一；不得只用可能冲突的生态型简称；group模式要求非空 |
| `variants.tsv` | `chromosome`, `position`, `ref`, `alt` | chromosome=1..5，1-based正整数，REF/ALT各为不同单碱基；四元组唯一；正式输入按 `(chr,pos,REF,ALT)` 严格排序。原始 multi-allelic site 必须在 VCF 导入时显式分解或排除，并留入 provenance |
| `phenotypes.tsv` | `accession_id`, `trait_id`, `value` | 每trait/accession最多一行；空值/NA/NaN视为缺失，拒绝无穷值；重复应回到汇总协议解决 |
| `provenance.json`（formal模式必需，`at_pheno_formal_v2`） | source、转换与全套 v2 信息绑定（完整键集合以代码 `REQUIRED_FIELDS` 为准） | `provenance_schema = "at_pheno_formal_v2"` 记录：逐项复检的运行重算 6 项 SHA256（`genotypes.npy`、`samples.tsv`、`variants.tsv`、`phenotypes.tsv`、trait-resolution registry、SHA256 绑定的 source-manifest JSON）＋ record-only 的 `source_vcf_sha256`（执行 gate 不重读 raw VCF；由 SHA256 绑定的 source-manifest 记录交叉绑定，raw-file 一致性核验在 dataset-build 阶段的 `verify_source_vcf`）；官方 source MD5（record-only：可执行层只校验 32-hex 形式，官方全等由带 `md5_matches_official` 的 manifest 记录承载）；过滤/multiallelic 策略状态、`TAIR10`、`ALT_dosage_0_1_2`、转换脚本/commit、请求 trait 的 `phenotype_registry resolved=true`（以 registry TSV 真值校验）；v1 记录被 formal gate 拒绝；细则见 [正式实验门禁](正式实验门禁.md) |

CLI按ID求交集并审计未匹配表型，不按行号直接拼标签。非目标性状不参与拟合。真实导入器必须检查缺失与倍性后再转换，不能把HDF5的0/1、PLINK编码和ALT dosage混为一谈。

`--splits`可提供冻结TSV：`accession_id, fold`（制表符），恰好覆盖当前trait的全部匹配样本，每个一次，非负fold编号。group模式检查每组不跨外层折；内层重新按剩余组LOGO，需要至少两个训练组。近亲分块内层尚未实现，不能仅输入分块outer manifest就宣称完整近亲隔离。

## 运行产物

每次使用新的 `runs/<run_id>/`，已有目录拒绝覆盖。中断产生的缺失产物不能算完成：以最后写出的 `provenance.json` 为完成记录。

- `audit.json`：样本/位点总量、交集、缺失、未匹配ID、群体分布。
- `config.json`、`splits.tsv`、`inner_splits_*.tsv`：本次全部设置与划分。
- `qc_outer_*.npz`及inner版本：eligible原列索引、训练means/frequencies/call_rates/MAC。
- `selected_outer_*.npz`：当前密度实际输入；inner选择可从对应QC、固定variants、salt与density重建。
- `tuning.json`：每outer/density的候选误差、选定alpha、内层与外层marker数、capped标志。
- `predictions.tsv`：每accession/density一次OOF；含y、prediction、train_mean、fold、alpha。
- `metrics.json`：逐折与pooled的additive/mean指标；`complete_oof=false`不可冒充全体结果。
- `omitted.json`：不可达到的密度等未执行项；同样真实marker集合的重复层级不代表独立比较。
- `provenance.json`：输入和源码SHA256、环境版本、git commit（尚无提交时null）、运行时间、pilot标记。

只有对应索引与原始variants/sample表和输入hash一同保留，压缩索引才可追溯。完成真实版本冻结后补充硬件、BLAS/CUDA、线程数、峰值内存和逐阶段计时，当前CPU pilot不声称做了完整性能benchmark。

## 与正式协议的差距

pilot不处理VCF/HDF5转换、祖源分层、近亲分块、LD、PC-only、RKHS、多核和SSM，也不输出显著性结论。全局hash只有近似染色体比例；inner用最多K的capped策略并留痕。group模式是公开标签的整组留出，不自动发现或修复标签质量。`genetic_group`不能直接拿国家字段冒充。

## formal provenance v2 (at_pheno_formal_v2)

formal gate（`gate_v2`）只接受 `provenance_schema = "at_pheno_formal_v2"` 记录。遗留 v1 记录（含 `input_sha256`/`genotype_representation` 字段但无 `provenance_schema`）在 pilot 仍可读，但 formal gate 拒绝，并指向 `provenance_schema` 字段。

记录须逐项记录、逐项验证的绑定（键集合以 `REQUIRED_FIELDS` 为准）：

- 本地重算 SHA256（4 项）：`genotypes_sha256`（= `genotypes.npy`）、`samples_sha256`（= `samples.tsv`）、`variants_sha256`（= `variants.tsv`）、`phenotypes_sha256`（= `phenotypes.tsv`）—— 均在 data 目录内，按本次运行重算。
- 按运行给入路径重算 SHA256（2 项）：`registry_sha256`（= 记录声明消费的那份 trait-resolution registry TSV，当前即 `data/manifests/trait_resolution_v1.tsv` 自身）与 `source_manifest_sha256`（= 本次运行给入的 SHA256 绑定的 source-manifest JSON）。合计 6 项在运行阶段重算；"SHA256 是 64 位串" 本身不构成验证，必须文件重算吻合。
- record-only：`source_vcf_sha256` — 执行 gate 只做 64-hex 形式校验与 manifest 记录的交叉绑定（manifest `local_sha256` == 本字段、`official_md5` == `official_source_md5`、`md5_matches_official: true`），不重读 19 GB raw VCF；raw-file 与官方同源的一至性核验在 dataset-build 阶段由 `at_pheno.formal_provenance.verify_source_vcf` 承担（重算该文件的 SHA256 + MD5 并对照 manifest 记录）。
- 仅记录状态：`official_source_md5`（官方 release MD5；gate 只校验其为 32 位小写十六进制，全等审判记录在 SHA256 绑定的 manifest）；`vcf_filter_policy` 与 `multiallelic_policy`（当前使用中的过滤/multiallelic 策略声明，非空字符串）；`conversion_script`（脚本路径）与 `conversion_commit`（git commit）。
- 域值：`reference_assembly` 必须为 `TAIR10`；`allele_encoding` 必须为 `ALT_dosage_0_1_2`。

除上述绑定之外，记录还带：`dataset_id`（非空字符串）、`notes`（字符串列表）、`phenotype_registry`（子记录 dict，请求 trait 必须 `trait_id` 匹配且 `resolved` 为 `true`；registry 处于其它状态时记录被拒——真值以运行重算的 registry TSV 为准）。

**重算而非信任规则**：gate 内不信任任何记录的 SHA 值。6 条本地绑定在每次运行都按盘上文件重算后比对，篡改必命中差异并按显式字段名（而非笼统的"hash 无效"）拒绝，例如 `phenotypes_sha256 mismatch...`。v1 记录一旦走 formal 通道，按 `provenance_schema` 缺失即拒绝。v2 绑定还使 gate 在输入改变时一并复核 `vcf_filter_policy`／`multiallelic_policy`／`allele_encoding` 三项状态声明；它们与登记 SHA 一同保证输入变化时验证也同步变化。

审计抽样／spot-check JSON 数据（`data/manifests/` 下）：[hdf5_vcf_position_mapping_summary](data/manifests/hdf5_vcf_position_mapping_summary.json)（3.3/3.4 位点映射与 spot-check）与 [1001g_v31_concordance_spot_check](data/manifests/1001g_v31_concordance_spot_check.json)（VCF 端小样本 spot-check）；它们为 `source_vcf_sha256` 与 filter policy 字段的下游验证提供交叉证据，但 **HDF5 0/1 orientation 的 REF/ALT 方向假设不属于本 gate 的冻结结论**（见 [正式实验门禁](正式实验门禁.md)）。
